# RP² and RP³ quadrupolar correlation decay

Lean formalizations of uniform log-square correlation decay in two-dimensional
projective spin models, with a compact Challenge/Solution interface for Palomar.

- [Paper](https://doi.org/10.5281/zenodo.23549037)
- [Original archived software](https://doi.org/10.5281/zenodo.23548847)
- [Palomar preparation, scope, and verification](PALOMAR.md)

This branch ports the archived release to **Lean 4.35.0-rc2** and Mathlib
`065356127b1dc0016f66b7283ce0ce2c4055aa55`. The original Lean 4.34.1 release
remains at tag `zenodo-2026-10-21`. Its historical hashes and audit records
refer to that original release, not this port.

## Mathematical result

For every finite coupling bound β ≥ 0 there are C > 0 and c > 0 such that

```text
|C_Q(x,y)| ≤ C exp(-c (log(2+r))²).
```

The constants are uniform over finite square-lattice subgraphs, signed edge
couplings bounded in absolute value by β, and observation sites. The distance
r is the integer lattice infinity distance. Spins are unit vectors in real
dimension 3 (RP²) or 4 (RP³), with normalized spherical product measure,
Gibbs weight `exp(Σ_e b_e (n_u · n_v)²)`, and observable
`(n_x · n_y)² - 1/3` or `- 1/4`. Independent sign changes leave the interaction
and observable invariant.

This bound excludes algebraic quadrupolar correlations within its stated scope.
It does not establish all-temperature exponential decay or exclude every
thermodynamic or topological transition. Additional local-limit,
high-temperature, and Fourier-regularity results remain in `RP2` and `RP3`;
the Comparator entry selects only the two finite-volume log-square bounds.

## Statement and proof

`Challenge.lean` imports only Mathlib and defines the actual model and both
statements. `Solution.lean` connects the same statements to the proved library
endpoints. `comparator.json` selects `ProjectiveDecay.rp2_log_square` and
`ProjectiveDecay.rp3_log_square`.

The deliberate `sorry` placeholders occur only in Challenge; the Solution
proofs must not depend on them. Shared definitions and theorem types are
generated by `scripts/generate-palomar-interface.py`. Comparator checks
that the actual proofs match the independently compiled statements.

## Reproduction

With the pinned toolchain, Git, and Python 3:

```sh
python3 scripts/check-lean-sources.py
python3 scripts/generate-palomar-interface.py --check
lake exe cache get
lake build
lake env lean SemanticWitnesses.lean
lake env lean RP3SemanticWitnesses.lean
lake env lean PalomarAxioms.lean
```

These local checks passed during preparation. On Linux with bubblewrap, run
`bash scripts/verify-comparator.sh` for the Comparator and independent-kernel
checks. The **Palomar preflight** GitHub workflow runs the official complete
mechanical check on an exact commit. That full check is still outstanding.
Submit at <https://submit.palomar-registry.org/> only after it passes.

See `PALOMAR.md` for the local environment limitation and historical tools.
Old standalone-bundle scripts and audit reports do not certify this port.
